# llm4orTT

唯一活动工程：桌面 `0.2版`；统一开发分支：`main`。工程目录名称与程序发布版本分开管理。历史副本统一存放在工程内的本地归档区。

[持续研究主入口](科研入口.md) · [研究质量与后续验证](research/研究质量与后续验证.md)

**从历史选择学习偏好，用可核验的证据检查和改进优化模型。**

llm4orTT 是一个面向优化建模可靠性的研究与应用项目。当前源码版本为 **0.1.2**，包含上下文逆优化工作台、精确模型比较、条件风险分析，以及配套实验和证据归档。

当前研究主线是：

> **在有限语义确认预算下，怎样选择需要确认的规则和需要接受的修改，提高优化模型修复的净收益？**

研究同时关注修复成功、把正确模型改错的风险，以及模型调用、语义确认和数值计算成本。

## 项目定位

项目目前有两组相互衔接的资产：

- **上下文逆优化**：根据已知模型、候选规则和历史决策估计偏好权重，分析哪些参数能够解释历史，以及推荐方案在声明条件下的风险。
- **模型核验与修复研究**：比较候选模型允许的决策和最优决策，生成精确反例，研究不同反馈、文本证据和修复策略的效果。

例如，历史排班可以帮助估计夜班和跨区支援的隐性代价；对于文字生成的排班模型，核验器可以进一步指出一条比例约束是否反向、某个本应允许的方案是否被排除。

应用界面、已有实验和后续方法研发分别记录状态。研究计划中的主动证据选择、风险约束修复和联合不确定性决策属于待验证扩展。

## 已实现能力

### 上下文逆优化工作台

- 结合已知成本与历史选择，估计共享的非负有界偏好权重。
- 支持线性特征和软约束惩罚；连续问题采用强对偶，整数问题采用前向分离。
- 提供候选筛选、正则化选择、残差、异常样本和经验参数范围。
- 对能够完整枚举的小型有界整数问题，计算联合相容参数集合上的条件风险界和风险见证。
- 支持误差预算敏感性、运行历史、输入输出与求解轨迹导出。
- 按需请求模型补充候选规则，复用缓存；工作台单次运行最多发起一次模型请求。
- 普通对话具有独立流程，支持多轮记录、停止、重试、附件和导出。

### 精确模型比较与研究模块

- 二维连续非负变量模型的精确几何比较。
- 一至六维连续非负变量模型的数值求解提议与有理数证书核验。
- 分别检查可行域、最优决策集合和求解状态；二维模块另提供目标排序诊断。
- 输出可代入重检的反例点与相关约束；证书不足时保留未决。
- 已有百分比语义规则、原文位置记录、局部修改、逐轮反馈与损伤测量工具。
- 已有一致采样、反馈粒度、可接受读法重打分和变形差分研究流程。

## 快速运行

### 环境

- Node.js 24或更新版本。
- Windows安装脚本下载固定版本的嵌入式Python。
- Linux/macOS使用Python 3.13及venv支持。
- 首次安装需要联网获取依赖；版本信息见[环境锁定](docs/solver-lock.json)。

在仓库根目录执行：

~~~sh
npm ci
npm run solver:prepare
npm run build
npm start
~~~

程序启动本地服务并打开浏览器。进入“逆优化工作台”，载入内置排班示例后运行即可。**内置示例无需API密钥。**

Windows桌面模式：

~~~sh
npm run desktop
~~~

开发模式：

~~~sh
npm run dev
~~~

需要模型辅助时，在“设置”中配置服务商、模型和密钥。逆优化工作台通过单独开关启用模型提案；普通对话使用独立流程。[DeepSeek兼容说明](docs/DEEPSEEK_COMPATIBILITY.md)

启用模型功能后，相应任务文本和上下文发送到所选服务商。密钥、聊天历史、运行缓存和结果保存在本机数据目录。

### Windows打包

~~~sh
npm run package
~~~

输出目录为release/0.1.2/win-unpacked/。运行打包程序时保留完整resources目录。维护源位于solver/和src/，修改后重新构建。

[发布页](https://github.com/Fiochanqwq/llm4orTT/releases)用于查看实际可取得的安装包；源码运行入口始终以本节为准。

## 研究方向与立项实验

### 已有证据给出的研究起点

已完成研究保存了候选共同错误、修复损伤、后续轮次停滞、参考读法敏感性和变形告警失败等现象。原始冻结结果和后续分析分别保留。

最新稿件：[决策集合核验预印本](research/artifacts/decision-contract-20261022/paper/main.pdf)。数值、逐题派生结果和复算范围见[论文与数值来源](research/artifacts/decision-contract-20261022/README.md)。

### 接下来要解决的问题

1. **证据从哪里来**：区分原文直接支持的要求、独立确认的样例、自动提取假设和完整参考反馈，记录获取成本。
2. **什么时候值得修改**：根据有依据的冲突选择局部编辑，保留已经核实的条件，支持拒绝、回退和停止。
3. **怎样取得下一条有用证据**：在有限确认次数与模型调用预算下，比较随机确认、分歧驱动确认与决策相关确认。
4. **怎样评价真实收益**：以最终实际交付模型为主，配对报告修复、退步、净收益、覆盖和成本。
5. **怎样处理错误证据**：评价缺失、方向错误和单位错误带来的影响，避免将错误规则永久锁定。

### 优先执行的三个立项实验

**A．固定可靠证据，检验修复策略。**  
确定性修改、测试驱动局部修复和新策略使用相同证据、初始候选和预算，检查算法本身的新增收益。

**B．改变证据覆盖与错误程度，检验可靠性。**  
比较证据缺失、方向错误、单位错误和错误样例下的修复与退步，区分条件保留与完整模型正确性。

**C．固定确认预算，检验证据选择。**  
比较随机确认、最大分歧确认与拟研发策略，同时计入语义确认、模型调用与求解成本。

先用开发数据验证机制和估算资源，再锁定新评价队列。旧响应用于开发与历史分析，新确认结果按原始题目身份划分，完整保留失败和未决状态。

### 方法范围

- 当前核验模块中的变量、单位和坐标解释需要明确给定。
- 部分语义证据只能证明其支持的事实；证据一致与完整模型正确分别评价。
- 对线性模型，允许全部已知正例就已经允许其凸包；凸包用于表达范围，方法增益通过证据获取和修改策略检验。
- 可行域核验与目标核验分别处理。
- 保留已检查条件是局部保证，真实退步由独立参考评价。
- 对参数恢复、决策质量和结构正确性分别设置指标。

新批次、模型费用和冻结规则按[任务板](任务.md)及[项目约定](AGENTS.md)执行。新方向先登记协议、队列、主对照和资源预算。

### 长期扩展

- 从固定方案风险检查推进到最小最大遗憾方案选择。
- 结合有限结构假设和偏好参数，研究联合不确定性下的决策。
- 主动选择历史和结构化询问，减少不影响决策的参数歧义。
- 在已有支持范围内扩展维度、题型和模型配置，再推进整数域与复杂映射。

### 直接相关工作

- [EquivaMap](https://proceedings.mlr.press/v267/zhai25a.html)：变量映射与模型等价。
- [ModelEquivBench](https://arxiv.org/abs/2607.29431)：多关系模型评价与证书。
- [COVER](https://journals.sagepub.com/doi/10.3233/FAIA260737)：反例定位、局部修改与测试回归保护。
- [Constraint Acquisition via Partial Queries](https://www.lirmm.fr/constraintacquisition/docs/papers/ijcai13-quacq.pdf)：主动约束查询。
- [Learn&Optimize](https://arxiv.org/abs/2111.11871)：未知约束网络下的学习与优化。

这些工作用于界定比较条件。新方法与基线使用相同可用信息和明确预算，核验器覆盖与修复器收益分别比较。

## 使用范围

- 逆优化输入需要已知模型骨架、历史决策和候选特征。
- 经验参数范围描述损失约束下的可行取值；统计置信区间另行估计。
- 条件风险依赖声明的参数框、误差预算、特征与可行域。
- 桌面风险证书使用完整动作枚举，面向小型有界整数问题。
- 合成日志、受控历史、真实模型响应和真实人工行为分别标注。
